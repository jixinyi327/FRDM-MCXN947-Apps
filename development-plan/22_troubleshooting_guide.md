# 故障排查手册

## 1. 板卡完全不亮

检查顺序：

1. J17 是否接对；
2. USB 线是否含数据/供电；
3. 换 USB 口和线；
4. J24 是否短接；
5. 是否同时从多个入口供电；
6. 是否有短路/异常发热；
7. D5 是否亮；
8. 3.3 V 是否正常。

不要一上来短接跳线或反复插拔；先确认电源路径。

## 2. PC 看不到 MCU-Link

- 用 Windows 设备管理器或 WSL `lsusb` 检查。
- 确认接的是 J17，不是 J11。
- WSL 需要 `usbipd bind/attach`。
- Windows 可能需要 LinkServer/MCU-Link 驱动。
- 若 D10 不亮，检查 MCU-Link 固件。

### MCU-Link ISP 恢复

1. 断开 USB；
2. 短接 J21；
3. 重新接 USB；
4. 运行 NXP 固件更新工具；
5. 断开，打开 J21，重新上电。

## 3. LinkServer 看不到探针

```bash
source development-plan/scripts/env.sh
LinkServer probes
```

- 检查 udev 权限；
- 检查 USB 直通；
- 检查其他 IDE 是否占用；
- 断开/重连；
- 确认使用 CMSIS-DAP 固件而不是损坏的 J-Link 固件。

## 4. 能识别探针但不能连接目标

- 确认 J19 开路（板载 MCU-Link）。
- 按住 SW3/ISP 后复位，尝试恢复。
- 检查目标电压和复位。
- 检查安全生命周期/调试认证。
- 检查代码是否立即进入低功耗或关闭调试。
- 检查 SWD 线/外部调试器连接。

Mass Erase 是最后手段，可能删除密钥和校准数据。

## 5. 没有 VCOM/串口

- J18 开路；
- 接 J17；
- 检查 Windows COM 或 WSL `/dev/ttyACM*`；
- 检查串口程序是否占用；
- 波特率 115200；
- 检查 P1_8/P1_9 是否被业务 GPIO 占用；
- 检查示例是否使用其他 UART；
- 检查 USB 直通的是否包含 VCOM 接口。

## 6. 串口乱码

- 时钟配置错误/晶振未起振；
- 波特率源不匹配；
- 8-N-1 设置错误；
- 电平不匹配；
- USB 转串口驱动/线路噪声；
- 代码打印过快导致缓冲溢出。

先用已知波特率发送固定字节，再用示波器测 TX 位宽。

## 7. 构建失败

| 错误 | 处理 |
|---|---|
| `ARMGCC_DIR` 未设置 | source `scripts/env.sh` |
| CMake 版本过低 | 使用 `.venv/bin/cmake` |
| `jsonschema`/`jinja2`/`requests` 缺失 | 安装 `scripts/05` 中的 Python 依赖 |
| 示例路径不存在 | 使用 `mcuxsdk/examples/...` |
| board/core 变量文件不存在 | `-b frdmmcxn947 -Dcore_id=...` |
| 旧 build 配置冲突 | `-p always` |
| 链接溢出 | 查看 `.map`，减少缓冲/模型或改用外部 Flash |

记录完整命令和工具版本，不要只截最后一行错误。

## 8. Flash 烧录失败

- 构建配置和链接地址不匹配；
- 外部 QSPI XIP 配置误烧到内部 Flash；
- Flash 写保护/安全生命周期；
- 目标低电压或复位不稳；
- 调试器时钟过快；
- Flash 器件不在 SDK 支持列表；
- 双核/多镜像没有按顺序烧录。

先烧简单 `hello_world` 验证物理链路，再烧自定义 Flash 映像。

## 9. Ethernet 不 Link

- 50 MHz 时钟；
- PHY 复位/strap；
- RJ45/变压器；
- MDIO/MDC；
- RMII 引脚配置；
- 摄像头改焊导致的引脚冲突；
- PHY 电源和地；
- 网线/交换机。

先读 PHY 寄存器，再抓 RMII 时钟和 TX/RX。

## 10. CAN 不回环/不通信

- loopback 软件配置；
- 收发器 standby；
- CAN_H/CAN_L 接反；
- 终端电阻；
- 位定时；
- 共地；
- 摄像头共享 P1_10/P1_11；
- 总线错误状态。

## 11. I3C 温度读取失败

- 地址 `0x48`；
- I3C/I2C 模式；
- P1_16/P1_17 网络；
- mikroBUS/摄像头是否占用；
- 上拉和 `P1_11/I3C1_PUR`；
- 总线电压；
- 例程是否与当前 SDK 匹配。

## 12. 摄像头黑屏/花屏

- SJ16/SJ26/SJ27 未改；
- 摄像头 I2C 地址/初始化；
- PCLK/VSYNC/HSYNC；
- 数据位序；
- 帧缓冲不足/越界；
- LCD 和摄像头 DMA 冲突；
- Ethernet/CAN 改焊冲突；
- 3.3 V I/O 和供电；
- 镜头/曝光。

## 13. 触摸漂移/误触

- 面板厚度/胶层；
- 接地和回流；
- 湿手/水膜；
- 电源噪声；
- P1_3 与 mikroBUS/MCU-Link 网络冲突；
- 温度漂移；
- 阈值/基线更新策略。

## 14. AI 推理太慢或 RAM 溢出

- 模型是否量化；
- NPU 是否真正启用；
- 不支持的算子是否回退 CPU；
- 输入尺寸；
- 模型权重是否占 SRAM；
- 激活/临时缓冲；
- 摄像头帧缓冲；
- 编译器版本/布局；
- 显示和网络是否抢占。

输出端到端时间和峰值 RAM，而不是只看模型参数量。

## 15. 电机一启动就过流/炸机

立即停止，断功率电源。检查：

- 相序；
- 死区；
- 上下桥直通；
- ADC 偏置/校准；
- 电流环符号；
- 编码器方向；
- 母线电压；
- 栅极驱动；
- 故障输入是否真正接入；
- 分流电阻型号；
- 功率板版本。

不要通过提高软件限流反复试错。

## 16. 双核通信失败

- 主/副核镜像版本；
- sysbuild 产物；
- 共享内存地址一致；
- 启动顺序；
- mailbox/RPMSG 通道；
- 内存屏障；
- 一侧复位后未重新初始化；
- 调试暂停导致超时。

## 17. 安全启动失败

- 密钥槽/签名；
- 镜像版本；
- 镜像地址；
- 生命周期；
- SB3 配置；
- 安全启动策略；
- 调试器写入的是否为完整镜像；
- 是否有双启动回退。

先保留可恢复 Bootloader，再实验不可逆策略。
