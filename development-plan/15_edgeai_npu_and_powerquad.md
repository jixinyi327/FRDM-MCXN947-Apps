# Edge AI、NPU 与 PowerQuad

## 1. 加速器分工

| 加速器 | 擅长 | 不擅长 |
|---|---|---|
| eIQ Neutron N1-16 NPU | 量化神经网络推理 | 未量化的大模型、通用浮点计算 |
| PowerQuad | 定点 FFT、滤波、矩阵、DSP | CNN、复杂控制流 |
| SmartDMA | 摄像头、显示、周期搬运 | 算法推理 |
| Cortex-M33 FPU/SIMD | 控制、预处理、小算子 | 大矩阵/高并行 CNN |

NPU 标称约 4.8 GOP/s，是器件级峰值能力，不等于任何模型都能达到该吞吐。

## 2. 典型模型边界

适合 MCXN947：

- 关键词识别；
- 小型图像分类；
- 人/物体检测的极小模型；
- 振动/电流时序异常检测；
- 简单姿态或手势；
- 设备状态分类。

不适合：

- 通用大语言模型；
- 高分辨率视频实时语义分割；
- 未量化的 FP32 视觉网络；
- 需要大量 DRAM 的多模态模型。

## 3. 模型部署流程

### 3.1 训练和量化

1. 在 PC 上训练；
2. 用目标数据做验证；
3. 做 INT8 量化感知或后训练量化；
4. 用校准集覆盖温度、光照、噪声和现场分布；
5. 对比 FP32 与 INT8 准确率；
6. 导出 NPU 支持的模型格式。

### 3.2 转换和编译

具体转换器以当前 eIQ/Neutron 工具链为准。流程通常为：

```text
训练框架 -> 中间格式 -> 量化/算子检查 -> NPU 编译
-> C 数组/二进制资源 -> SDK 工程链接
```

必须检查：

- 不支持算子是否回退 CPU；
- 张量布局和 padding；
- 模型常量是否放外部 Flash；
- 输入/输出对齐；
- 最大临时缓冲；
- 编译器版本与 SDK 版本匹配。

### 3.3 板上集成

1. 先用预置模型跑通；
2. 再替换成自己的模型；
3. 用固定输入做 PC/CPU/NPU 对拍；
4. 记录单次推理周期和峰值 RAM；
5. 接入真实摄像头/传感器；
6. 做长时间稳定性测试。

## 4. 内存预算

```text
模型权重 + 激活缓冲 + 输入张量 + 输出张量
+ 预处理缓冲 + 后处理 + 摄像头帧
+ RTOS/网络/日志 + 栈
<= 可用 SRAM
```

模型权重可以常驻外部 QSPI Flash，但推理时可能仍需缓冲和解压空间。摄像头 480×320 单帧已约 300 KB，因此视觉模型输入通常应缩小或做 ROI。

## 6. 性能测量

至少记录：

- 模型版本/哈希；
- 量化方案；
- 输入尺寸和格式；
- NPU 推理时间；
- CPU 预处理/后处理时间；
- 端到端帧率；
- 最大/最小剩余堆；
- 功耗与温度；
- 准确率和误报率。

不要只报告“NPU 多少 GOP/s”。产品关心的是端到端延迟、能耗和准确率。

## 7. 视觉系统注意事项

- 摄像头与 Ethernet/CAN 有焊桥冲突；
- 摄像头时钟、VSYNC、HSYNC、PCLK 要稳定；
- SmartDMA 与 CPU 共享内存要有明确所有权；
- DMA 缓存/一致性按参考手册和 SDK 配置处理；
- 显示和推理同时运行会竞争内存带宽；
- 曝光变化会破坏模型，需要训练数据覆盖；
- 低分辨率不必然低延迟，预处理可能成为瓶颈。

## 8. PowerQuad 使用建议

PowerQuad 适合：

- FFT/IFFT；
- FIR/IIR；
- 矩阵乘法；
- 定点数学；
- 电机控制/电能计量的信号处理。

开发顺序：

1. 软件参考实现；
2. PowerQuad 实现；
3. 定点误差和溢出分析；
4. 周期和功耗对比；
5. 与 ADC/DMA 触发集成。

## 9. AI 验收门禁

- 模型精度在量化后满足指标；
- 现场数据集覆盖真实光照/噪声；
- 最坏情况 RAM 不越界；
- 端到端延迟满足控制/显示需求；
- 断帧、丢帧和传感器异常可恢复；
- 长时间运行无热降频或内存泄漏；
- 模型和固件都可安全升级。
