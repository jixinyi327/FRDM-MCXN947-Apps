# TrustZone、安全启动与固件升级

## 1. 安全能力概览

MCXN947 提供：

- Arm TrustZone；
- EdgeLock Secure Enclave；
- EdgeLock 公钥加速；
- PUF 设备身份；
- DICE 设备证明；
- 安全密钥存储和使用策略；
- AES-256、SHA-2、ECC P-256、TRNG；
- 不可变 ROM 安全启动；
- SB3 镜像格式、XIP 加密和认证；
- 双安全启动模式；
- 安全认证调试；
- 设备生命周期；
- 防拆/电压/温度/光照/时钟/毛刺监测。

这是一套硬件安全根，不是完整产品安全方案。

## 2. 先定义威胁模型

在写代码前回答：

- 设备会被谁物理接触？
- 固件是否允许降级？
- 调试口何时关闭？
- 密钥在哪里生成、注入和备份？
- 设备身份如何证明？
- 现场升级由谁签名？
- 升级失败如何恢复？
- 日志/配置中是否包含隐私数据？

没有威胁模型时，直接开启安全启动常导致不可维护的现场设备。

## 3. TrustZone 分区

常见分区：

| 安全世界 | 非安全世界 |
|---|---|
| 密钥与证书 | UI |
| 安全启动/升级验证 | 普通通信协议 |
| 设备身份/证明 | 文件系统 |
| 安全存储 | 应用业务 |
| 调试生命周期控制 | 日志显示 |

设计要点：

- 安全服务通过受控 API 调用；
- 共享内存显式定义输入/输出和最大长度；
- 不把密钥放入非安全世界指针可访问区域；
- MPU/SAU/TRDC 配置要覆盖所有总线和外设；
- 安全/非安全中断和异常路径都要测试；
- 尽量让安全世界代码小、可审计。

## 4. 安全启动

典型链路：

```text
不可变 ROM
-> 校验 Bootloader / SB3 镜像签名
-> 校验版本/回滚策略
-> 解密/认证执行区
-> 启动应用
```

数据手册列出的安全启动支持包括 ECDSA P-256/P-384，以及 SB3 的恢复/更新能力。具体镜像工具、密钥槽、双启动配置以参考手册和 SDK 的 `els_pkc`、`tfm`、`ota` 示例为准。

## 5. 固件升级架构

建议采用：

- 签名清单，包含版本、硬件 ID、最小可回滚版本；
- A/B 或主备镜像；
- 下载区与执行区分离；
- 升级前检查电池/电源条件；
- 校验完整后再提交启动指针；
- 启动失败自动回退；
- 防降级和密钥轮换；
- 升级日志与远程告警；
- 生产/开发密钥严格分离。

SDK 示例包括：

- `examples/ota_examples/ota_rom_basic`
- `examples/ota_examples/ota_mcuboot_basic_psa`
- `examples/ota_examples/ota_mcuboot_server/enet`
- `examples/tfm_examples/...`

## 6. 生命周期和调试

调试口通常是开发效率和安全性的矛盾点：

- 开发阶段允许认证调试；
- 样机阶段限制认证范围；
- 量产阶段关闭或仅允许受控认证调试；
- 返修阶段需要受控恢复策略。

生命周期切换、密钥熔断、Mass Erase、IFR/OTP 编程都可能不可逆。必须：

1. 在独立评估板上验证；
2. 记录初始状态和每一步结果；
3. 不把唯一密钥放在一台电脑；
4. 准备离线应急恢复；
5. 让第二个人复核命令。

## 7. 密码学实现

优先使用 PSA Crypto/ELS 硬件加速和经过验证的库：

- 不自行实现密码算法；
- 使用安全随机源；
- 签名验证失败立即拒绝；
- 避免时序泄漏；
- 对密钥使用设置策略；
- 不把私钥明文写入 Flash；
- 证书验证包括主机名、有效期和吊销策略；
- 对固件和模型都做哈希/签名。

## 8. 抗物理攻击

可利用：

- 防拆检测；
- 电压/温度/光照/时钟监测；
- 毛刺检测；
- 安全调试；
- 内存加密/认证。

但物理防护需要与外壳、PCB、传感器、电池、日志销毁和维修流程结合。只开寄存器功能不等于达到目标攻击成本。

## 9. 安全测试

- 错误签名；
- 截断镜像；
- 回滚攻击；
- 版本不匹配；
- 证书过期；
- 断电中断升级；
- 调试口认证失败；
- 安全世界非法指针；
- 非安全世界尝试访问安全外设；
- 防拆触发；
- 电压/时钟异常；
- 密钥撤销和设备身份轮换。

## 10. 开发门禁

- 安全/非安全边界图已评审；
- 密钥生命周期文档已评审；
- 升级回滚已在板卡验证；
- 量产和开发密钥隔离；
- 调试生命周期流程可恢复；
- 所有失败路径都不会留在未验证镜像；
- 评估板 EdgeLock 2GO provisioning 状态已确认。
