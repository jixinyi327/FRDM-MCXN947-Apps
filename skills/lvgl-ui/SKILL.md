# LVGL UI

优秀 LVGL UI = 通用 UI 原则 + 嵌入式资源约束 + LVGL 工程可维护性。目标是让界面
目的明确、状态一致、可交互、能稳定运行，并且后续可以由其他人修改。

## 适用范围

本 Skill 负责：

- 信息架构、主任务和操作层级；
- 颜色、字体、尺寸、间距、状态和组件样式；
- 中英文/多语言文案、默认语言、切换流程和字体子集；
- 触控命中、焦点、反馈、错误恢复和破坏性操作；
- 图片、字体、动画和层级资源的设计预算；
- 纯 C 与 XML/Pro 工程的代码组织和命名。

当项目另有显示性能 Skill 时，同时使用两者：

- 本 Skill 决定“界面如何设计和组织”；
- 平台 Skill 决定“显示链路如何刷新、同步并满足硬件时序”。

本 Skill 不替代目标硬件的实测，也不得用编译成功证明视觉验收通过。

## 强制工作流

### 1. 定义屏幕任务

- 为每个屏幕写一句唯一主任务。
- 标出首屏主操作、次要操作和二级功能。
- 删除没有用户目的或状态意义的控件。
- 默认值必须可解释；隐藏操作必须有可见入口或提示。

### 2. 建立样式和令牌

- 在编写页面之前建立统一的设计令牌与样式注册表。
- 颜色、字体、圆角、边框、间距和常用状态必须通过命名样式复用。
- 同类按钮的 `pressed`、`focused`、`disabled`、`checked` 外观必须一致。
- 使用 `LV_PART_* | LV_STATE_*` 建模状态，使用
  `lv_style_transition_dsc_t` 配置状态过渡。
- 页面代码允许设置布局、位置和业务相关尺寸，但不得散落重复配色和状态样式。

样式实现模式见
[references/design-tokens-and-styles.md](references/design-tokens-and-styles.md)。

### 3. 规划本地化与字体

- 所有可见文案通过稳定文本 ID 和统一翻译表获取。
- 默认语言必须由产品需求明确，初始化时确定性设置。
- 语言切换必须覆盖静态标签、动态状态、菜单、信息栏、模态框和错误反馈。
- 非 ASCII 文本启用 UTF-8，并显式关闭 ASCII 文本编码。
- 使用压缩字形时同时启用对应字体解压配置；字体生成格式与 LVGL 配置必须匹配。
- CJK 使用从翻译表生成的字体子集，覆盖所有 UI 字号和格式化字符。
- 文案变化后重新生成字体，并检查字形覆盖、缺字、截断和双向切换。

中英文实现、字体配置和验收矩阵见
[references/localization.md](references/localization.md)。

### 4. 设计交互

- 触控目标建议至少 `38x38 px`；尺寸不足时使用
  `lv_obj_set_ext_click_area()` 扩展命中区。
- 圆角、阴影或透明背景不得缩小心理上的可点击范围。
- 按钮、开关、滑块和自定义控件必须有即时视觉反馈。
- 长操作显示进度或忙碌状态；阻塞工作不得直接卡住 UI 任务。
- 删除、重置、恢复出厂等破坏性操作必须有确认，并提供取消路径。
- D-pad 或编码器界面必须建立焦点组，定义初始焦点、移动顺序和恢复规则。
- 自定义可聚焦控件负责 Enter 的视觉状态和业务动作。

焦点、命中和容错规则见
[references/interaction-and-focus.md](references/interaction-and-focus.md)。

### 5. 先做资源预算

- 在设计阶段估算帧尺寸、刷新区域、动画面积、图片解码和字体覆盖。
- 避免全屏半透明叠层、每帧全屏渐变、超大 ARGB 图片和无边界动画。
- 图片按最终显示尺寸准备；字体按最终 px 和语言字符集验证。
- 设计要在目标 MCU 上实测，不以桌面模拟器结果代替。
- 平台已有双缓冲、DMA、TE 或分核方案时，不得自行破坏其所有权和时序约束。

预算方法和优化顺序见
[references/embedded-resource-budget.md](references/embedded-resource-budget.md)。

### 6. 实现并组织工程

- 不编辑工具生成的 C/H 文件；生成物与手写代码分离。
- 组件尺寸优先使用 flex/grid、百分比和内容尺寸。
- 避免容器和子元素同时锁定固定宽高导致无法适配。
- 命名前缀固定为 `style_`、`font_`、`icon_`、`img_`、`wd_`。
- XML/Pro 工程使用可复用 `style_` 样式，不在页面节点堆叠内联样式。
- 纯 C 工程把令牌、样式、组件和页面状态分层，不让页面承担全部样式细节。

代码组织、命名、生成代码和 XML/Pro 策略见
[references/maintainability-and-naming.md](references/maintainability-and-naming.md)。

### 7. 审查和验收

- 先运行可用项目脚本和构建；再逐项执行下方检查清单。
- 对照每个屏幕的慢操作、快速操作、错误操作、取消和返回路径。
- 使用真实触控面板检查可读性、命中区、动画和闪烁。
- 焦点设备使用真实方向键、编码器或等价输入验证。
- 记录仍未完成的物理验收项，不得推断为通过。

可使用结构审计脚本发现明显风险：

```bash
bash scripts/audit_lvgl_ui.sh <ui-source-directory>
```

纯触摸项目可设置 `LVGL_UI_INPUT=touch`，明确焦点组不属于当前输入范围。

该脚本只做启发式审计，不能替代代码审查、内存测量和实机测试。

## 不可妥协的约束

1. 一个屏幕只有一个主任务，主操作必须一眼可见。
2. 同类控件必须复用同一套命名样式和状态选择器。
3. 触控目标不足时必须有扩展命中区。
4. 关键操作必须有视觉反馈、错误恢复和取消路径。
5. 破坏性操作不得单击立即执行。
6. 编码器/D-pad 界面不得依赖触摸式隐藏路径。
7. 不编辑生成文件，不让页面与资源生成器互相覆盖。
8. 资源设计必须符合目标 MCU 的 RAM、Flash、带宽和刷新预算。
9. 页面切换和状态变化不能破坏平台已建立的显示所有权。
10. 所有可见文案必须走统一翻译源，不能散落在页面里形成无法同步的双语实现。
11. 含非 ASCII 文本时必须验证 UTF-8 配置和字体字形解码配置。
12. 编译通过、样式构建通过或静态检查通过，都不等于实机 UI 验收通过。

## 提交前检查清单

### 认知与信息架构

- [ ] 每个屏幕都有一句唯一主任务。
- [ ] 首屏主操作无需寻找即可发现。
- [ ] 每个控件都有明确目的、状态或操作。
- [ ] 高级功能已移入二级入口，而非堆满首屏。
- [ ] 默认值和隐藏入口有可见提示，无记忆负担。
- [ ] 用户能在数秒内理解“在哪、能做什么、下一步点哪”。

### 样式与状态

- [ ] 颜色、字体、圆角、边框和间距来自命名令牌。
- [ ] 同类控件复用同一套 `lv_style_t`。
- [ ] 页面没有复制粘贴的重复内联状态样式。
- [ ] `pressed`、`focused`、`disabled`、`checked` 在每个屏幕一致。
- [ ] 状态使用 `LV_PART_* | LV_STATE_*` 建模。
- [ ] 状态变化使用统一时间曲线和 `lv_style_transition_dsc_t`。
- [ ] XML/Pro 使用 `style_` 可复用样式，无内联配色堆叠。

### 交互与容错

- [ ] 触控目标达到 `38x38 px` 或已设置扩展命中区。
- [ ] 小图标、透明边缘和圆角控件仍可稳定点击。
- [ ] 所有操作都有即时视觉反馈。
- [ ] 长操作有进度、忙碌状态或明确的完成反馈。
- [ ] 破坏性操作有确认和取消路径。
- [ ] 配置修改后显示明确的成功、失败或未改变状态。
- [ ] 编码器/D-pad 焦点顺序可预测，初始和返回焦点已定义。
- [ ] 错误操作后可以返回、重试或恢复，不形成死路。

### 本地化与字体

- [ ] 所有可见文案通过稳定文本 ID 和单一翻译表获取。
- [ ] 默认语言已由产品需求明确并可复现。
- [ ] 语言切换会更新静态标签、动态状态、菜单、信息栏、模态框和错误反馈。
- [ ] 格式化文本使用完整模板，没有拼接不可翻译的半句。
- [ ] 非 ASCII 文本启用 `LV_TXT_ENC_UTF8` 并禁用 ASCII 编码。
- [ ] 压缩字形与 `LV_USE_FONT_COMPRESSED` 配置一致。
- [ ] CJK 字体子集覆盖全部翻译字符、数字和标点。
- [ ] 文案修改后已通过项目脚本重新生成字体。
- [ ] 中文无方框、空白、乱码或缺字。
- [ ] 英文无中文残留，布局无截断。
- [ ] 中英文双向切换后，页面和动态状态保持一致。
- [ ] 冷启动和重启后的默认语言符合需求。

### 资源与性能

- [ ] 已估算目标帧尺寸、动画面积和有效刷新带宽。
- [ ] 没有无必要的全屏透明度、阴影、模糊或复杂渐变。
- [ ] 图片已按目标分辨率、格式和内存占用处理。
- [ ] 字体已按最终字号和目标语言验证可读性与覆盖。
- [ ] 动画只影响必要区域，并可在目标硬件上持续运行。
- [ ] 未破坏平台的双缓冲、DMA、TE 或分核约束。
- [ ] 已在目标硬件测量 RAM、Flash、帧时间和交互流畅度。

### 工程与维护

- [ ] 命名使用 `style_`、`font_`、`icon_`、`img_`、`wd_` 前缀。
- [ ] 生成的 C/H 文件未被手工修改。
- [ ] 资源、样式、组件和业务逻辑分离。
- [ ] 组件使用 flex/grid 或相对尺寸，未发生双重固定尺寸。
- [ ] 纯 C 和 XML/Pro 各自采用对应的可维护性策略。
- [ ] 删除或替换样式时没有遗留不可达资源。
- [ ] 实机视觉、焦点和错误路径已完成验收或明确标记待验收。
