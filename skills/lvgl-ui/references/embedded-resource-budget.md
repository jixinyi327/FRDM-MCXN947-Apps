# 嵌入式资源预算

## 基础计算

```text
frame_bytes = width * height * bytes_per_pixel
stripe_bytes = width * stripe_height * bytes_per_pixel
bandwidth = transferred_bytes * frames_per_second
```

还需要计入：

- LVGL draw buffer；
- 图片解码和目标格式内存；
- 字体覆盖与字形缓存；
- 每个动画层的临时缓冲；
- 其他 CPU 核和业务模块的 RAM。

## 视觉设计风险

优先减少：

- 全屏透明度叠层；
- 全屏阴影、模糊和高半径复杂遮罩；
- 每帧变化的全屏渐变；
- 超出实际显示尺寸的图片；
- 持续运行且覆盖大面积的动画；
- 同一帧内同时变化的多个大对象。

局部动画优先：只失效发生变化的控件区域，避免整屏重绘。

## 图片

- 按实际显示分辨率准备源图。
- 优先使用目标端原生格式，避免运行时缩放。
- RGB565 屏幕优先使用 RGB565 或合适的带透明度格式。
- 检查 stride、对齐、缓存和 DMA 可访问性。
- 大图优先放外部存储并测试读取带宽，不假设 Flash 读取免费。

## 字体

- 在目标屏幕和最终字号下检查最小文字。
- 只包含目标语言和字符集，避免整库打包。
- 字体过大时考虑压缩位图字体。
- 长文本使用换行、截断或局部滚动，明确其失效区域。

## 刷新

- 平台已有双缓冲、DMA、TE 或分核方案时，沿用平台约束。
- 调整 SPI/并行时钟必须基于电气限制、波形和错误率验证。
- 理论帧率不等于可达帧率；以目标硬件测量为准。
- 帧率、输入延迟和 CPU 占用必须一起评估。

LVGL 官方 FAQ 中关于 display、DMA、draw buffer 和性能的建议可作实现参考，但
必须结合当前控制器、内存所有权和板级时序验证。
