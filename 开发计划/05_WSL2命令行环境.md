## 3. 从零复现的步骤

以下步骤用于换机或修复环境。已完成的目录可以跳过。

### 3.1 Python 虚拟环境

```bash
mkdir -p /home/jxy/NXP/MCXN947
cd /home/jxy/NXP/MCXN947
python3 -m venv .venv

# 本机直连 PyPI 曾出现 SSL EOF，使用文档建议的镜像
.venv/bin/pip install -U pip \
  -i https://pypi.tuna.tsinghua.edu.cn/simple

.venv/bin/pip install \
  -i https://pypi.tuna.tsinghua.edu.cn/simple \
  'west>=1.2' 'cmake>=3.30,<4' ninja jsonschema requests jinja2 pyserial pyelftools
```

### 3.2 Arm GNU Toolchain

```bash

curl -L --retry 5 \
  -o downloads/arm-gnu-toolchain-14.2.rel1-x86_64-arm-none-eabi.tar.xz \
  'https://developer.arm.com/-/media/Files/downloads/gnu/14.2.rel1/binrel/arm-gnu-toolchain-14.2.rel1-x86_64-arm-none-eabi.tar.xz'

tar -xJf downloads/arm-gnu-toolchain-14.2.rel1-x86_64-arm-none-eabi.tar.xz -C toolchains
```

### 3.3 SDK 工作区

```bash
export PATH="/home/jxy/NXP/MCXN947/.venv/bin:$PATH"
```

目标板清单会下载约 7.7 GB，包含 AI、网络、USB、LVGL、安全、电机和其他中间件。初次同步在本机耗时约 8 分钟，主要时间在 ExecuTorch 等子模块。

### 3.4 LinkServer

NXP 的 Linux 安装器通常要求 sudo。当前已用“解包后使用”的方式放入项目目录：

```bash
curl -L --retry 3 \
  -o downloads/LinkServer_26.9.130.x86_64.deb.bin \
  'https://www.nxp.com/lgfiles/updates/mcuxpresso/LinkServer_26.9.130.x86_64.deb.bin'

chmod +x downloads/LinkServer_26.9.130.x86_64.deb.bin

# 非交互解包；空 DISPLAY 避免安装器尝试打开 X 终端
env DISPLAY= downloads/LinkServer_26.9.130.x86_64.deb.bin \
  --noexec --target downloads/linkserver_extract

mkdir -p tools/linkserver
dpkg-deb -x \
  downloads/linkserver_extract/LinkServer_26.9.130.x86_64.deb \
  tools/linkserver
```

这种方式不注册系统路径和 udev 规则，所以必须使用 `env.sh` 设置的路径；USB 权限需按下节处理。

## 4. WSL2 的 USB 直通

当前 Windows 尚未安装 `usbipd`，WSL 中也未看到 MCU-Link。需要使用管理员 PowerShell 在 Windows 主机操作：

```powershell
winget install --interactive --exact dorssel.usbipd-win
usbipd list
```

找到 FRDM-MCXN947 的 MCU-Link/CMSIS-DAP 条目后：

```powershell
# 第一次绑定需要管理员权限
usbipd bind --busid <BUSID>

# 连接到当前 WSL
usbipd attach --wsl --busid <BUSID>
```

然后在 WSL 检查：

```bash
lsusb
ls -l /dev/ttyACM* /dev/ttyUSB*
LinkServer probes
```

若重新插拔或 WSL 重启，通常需要再次 `usbipd attach`。

## 5. udev 权限

LinkServer 的规则文件位于：

```text
/home/jxy/NXP/MCXN947/tools/linkserver/lib/udev/rules.d/85-linkserver_26.9.130.rules
```

在可输入 sudo 密码时执行：

```bash
bash /home/jxy/NXP/MCXN947/开发计划/scripts/install_udev_rules.sh
```

当前用户属于 `dialout`、`plugdev`，这对串口有帮助，但不能替代调试器 udev 规则。若 LinkServer 只能以 root 访问探针，不要长期用 root 开发，应修正 udev 规则。

## 7. SDK 更新策略

量产项目应固定 SDK 版本和 manifest revision，不要长期跟随 `latest`。

```bash
cd "$MCXN_SDK/manifests"
git rev-parse HEAD
cd ..
west list > sdk-revisions.txt
```

升级时新建工作区验证，不要直接覆盖正在开发的工作区。记录：

- SDK tag/commit；
- GCC 版本；
- CMake/Ninja/LinkServer 版本；
- 与上游 SDK 的本地补丁；
- 已通过的板级测试集。

## 8. 常见环境问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `west: unknown command "update_board"` | 不在 workspace 根目录 | `cd "$MCXN_SDK"` |
| `Please set ARMGCC_DIR` | 未 source `env.sh` | source 后重试 |
| CMake 3.28 警告 | 系统 CMake 低于推荐 3.30 | 使用 `.venv/bin/cmake` |
| west 导入时报 `jinja2/requests` 缺失 | SDK 工具扩展依赖未装齐 | 重新安装本文件第 3.1 节依赖 |
| `examples/... does not exist` | 使用旧文档相对路径 | 从 workspace 根目录使用 `mcuxsdk/examples/...` |
| `_boards/frdmmcxn947@...` 不存在 | 把 core 写进了 board 目录 | build 用 `-b frdmmcxn947 -Dcore_id=cm33_core0` |
| 找不到 USB 探针 | WSL 未直通 | 检查 `usbipd list/attach` |
